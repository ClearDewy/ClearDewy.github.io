                                  # 云原生

                                  # Docker

                                  Docker 是一个开源的应用容器引擎，允许开发者打包他们的应用及依赖包到一个可移植的容器中，然后发布到任何流行的 Linux 机器上，也可以实现虚拟化。容器是完全使用沙盒机制，相互之间不会有任何接口。

                                  # 了解容器的特性

                                  # 轻量化

                                  • 资源占用小：与传统的虚拟机相比，Docker 容器不需要额外负载一个完整的操作系统实例，因此占用的系统资源更少。容器直接运行在宿主机的内核上，不需要虚拟化层次，从而提供更高效的资源利用。

                                  • 快速启动：由于不需要启动完整的操作系统，容器可以在几秒钟内启动。这为开发和部署提供了极大的灵活性和效率。

                                  • 高效的系统资源利用：容器共享宿主机的操作系统内核，而不是每个容器都有自己的操作系统。这意味着它们占用更少的系统资源（如内存和处理能力）。

                                  # 标准开放

                                  • 容器标准化：Docker 容器的一个关键特性是它们的标准化。Docker 提供了一个标准的容器格式，使得容器可以在不同的环境和平台上一致运行。

                                  • 应用隔离：容器包括应用程序及其全部依赖，这确保了应用在不同环境中的一致性和可移植性。

                                  • 开放源代码：Docker 是开源的，这意味着任何人都可以贡献代码，审查代码库并提出功能改进。

                                  # 安全隔离

                                  • 沙箱环境：每个 Docker 容器都在一个沙箱环境中运行。即使是在同一台宿主机上，每个容器也是相互隔离的，提供了安全保障。

                                  • 资源限制：可以设置资源限制来控制每个容器可以使用多少宿主机的资源，如CPU、内存等，这提高了整体的系统稳定性。

                                  • 网络隔离：容器之间的网络是可配置的，可以进行隔离，确保网络安全和隐私。

                                  # 了解容器与虚拟机的区别

                                  # 虚拟化机制

                                  • 虚拟机（VM）：

                                    • 完全虚拟化：虚拟机提供了完全的操作系统虚拟化。这意味着每个虚拟机都运行着自己的操作系统实例。

                                    • 硬件级别虚拟化：虚拟机通过虚拟化硬件来实现，通常需要额外的虚拟化软件（如VMware或Hyper-V）来模拟整个硬件系统。

                                  • 容器：

                                    • 操作系统级别虚拟化：容器则是在操作系统级别进行虚拟化。它们共享宿主机的操作系统内核，但在用户空间中运行隔离的进程。

                                    • 轻量级：容器不需要整个操作系统的副本，这使它们比虚拟机更轻量级。

                                  # 启动速度

                                  • 虚拟机：虚拟机启动速度相对较慢，因为它们需要加载并运行整个操作系统，这个过程可能需要几分钟。

                                  • 容器：容器的启动速度非常快，通常只需要几秒钟。这是因为容器共享宿主机的操作系统内核，并且不需要单独的操作系统启动过程。

                                  # 资源消耗

                                  • 虚拟机：

                                    • 更高的资源需求：由于每个虚拟机都运行着完整的操作系统，因此它们通常消耗更多的内存和处理资源。

                                    • 资源隔离：虚拟机提供了良好的资源隔离，因为它们在各自独立的虚拟硬件上运行。

                                  • 容器：

                                    • 更高效的资源利用：容器共享宿主机的内核，但隔离应用程序和其依赖，这使得它们能够更高效地使用资源。

                                    • 密集部署：由于资源使用效率高，可以在同一硬件上运行更多的容器实例。

                                  # 掌握镜像打包、容器启动等基本使用

                                  # Dockerfile编写

                                  Dockerfile 是一个文本文件，包含了一系列的命令和参数，用于自动构建一个 Docker 镜像。

                                  • 基础镜像（Base Image）:

                                    • 使用 FROM 指令指定基础镜像。例如: FROM ubuntu:18.04。

                                    • 基础镜像是构建新镜像的基础，通常是一个轻量级的操作系统，如 Ubuntu、Alpine。

                                  • 维护者信息（Maintainer）:

                                    • 使用 LABEL 指令添加维护者信息。例如: LABEL maintainer="name@example.com"。

                                  • 运行命令（RUN）:

                                    • 使用 RUN 指令执行命令，用于安装软件或者配置环境。例如: RUN apt-get update && apt-get install -y nginx。

                                    • 每个 RUN 指令都会在当前镜像的顶层添加一个新层。

                                  • 添加文件（ADD 和 COPY）:

                                    • COPY 用于复制本地文件到镜像中。例如: COPY . /app。

                                    • ADD 类似于 COPY，但它还可以用于自动解压缩归档文件和远程 URL。

                                  • 设置工作目录（WORKDIR）:

                                    • WORKDIR 用于设置工作目录。例如: WORKDIR /app。

                                  • 环境变量（ENV）:

                                    • 使用 ENV 设置环境变量。例如: ENV NODE_ENV production。

                                  • 对外暴露端口（EXPOSE）:

                                    • EXPOSE 指令用于指定容器运行时的端口。例如: EXPOSE 80。

                                  • 运行指令（CMD 和 ENTRYPOINT）:

                                    • CMD 设置容器启动后默认执行的命令和参数。例如: CMD ["node", "app.js"]。
                                    • ENTRYPOINT 的用法和 CMD 类似，但用于设置容器作为可执行文件使用。

                                  • 其他指令:

                                    • 如 VOLUME（定义挂载点）、ARG（构建参数）等。
                                  # 1、容器打包构建

                                  • 编写 Dockerfile: 根据需要构建的应用编写 Dockerfile。

                                  • 构建镜像:

                                    • 在 Dockerfile 所在目录运行 docker build -t [tag-name] . 命令。

                                    • 例如：docker build -t myapp:1.0 .。

                                  • 运行容器:

                                    • 使用 docker run 命令启动容器。例如：docker run -d -p 5000:80 myapp:1.0。

                                  # docker ps

                                  # 1、查看容器进程

                                  docker ps 命令用于查看 Docker 中当前正在运行的容器进程。这个命令会列出所有正在运行的容器的信息，包括容器 ID、创建时间、正在使用的镜像、命令、容器的名字以及端口信息等。

                                  • docker ps : 列出所有当前正在运行的容器。
                                  • docker ps -a : 列出所有容器，包括正在运行的和已停止的。
                                  • docker ps -q : 仅显示容器 ID。
                                  • docker ps --format : 使用自定义格式显示容器列表。

                                  # docker run

                                  # 1、启动容器

                                  docker run 命令是 Docker 中用来启动新容器的主要命令。它会从一个指定的镜像创建一个新的容器实例，并执行其中的应用程序。这个命令有许多选项，可以用来定制容器的运行方式。

                                  • 基本启动：只需提供镜像名，Docker 会创建并启动一个新的容器。docker run [IMAGE]

                                  • 交互式模式：使用 -it 选项，可以启动一个交互式的容器，通常用于需要终端交互的应用。docker run -it [IMAGE]

                                  • 后台运行：使用 -d（detached）选项，可以让容器在后台运行。docker run -d [IMAGE]

                                  • 命名容器：使用 --name 选项给容器指定一个名称。docker run --name [NAME] [IMAGE]

                                  • 端口映射：使用 -p 选项将容器内的端口映射到宿主机的端口。docker run -p [HOST_PORT]:[CONTAINER_PORT] [IMAGE]

                                  • 环境变量：使用 -e 选项设置环境变量。docker run -e "[VAR]=[VALUE]" [IMAGE]

                                  • 挂载卷：使用 -v 选项挂载宿主机的目录或文件到容器中。docker run -v [HOST_DIRECTORY]:[CONTAINER_DIRECTORY] [IMAGE]

                                  # docker logs

                                  # 1、查看容器日志

                                  基本语法：

                                  docker logs [OPTIONS] CONTAINER

                                  其中 CONTAINER 是想要查看日志的容器的 ID 或名称。

                                  • -f 或 --follow ：实时跟踪日志输出。docker logs -f [CONTAINER]

                                  • --since：显示自某个时间点以来的日志。docker logs --since [TIME] [CONTAINER]

                                  • --tail ：仅显示最后几行日志。docker logs --tail [NUMBER_OF_LINES] [CONTAINER]

                                  • -t 或 --timestamps：在每条日志前添加时间戳。docker logs -t [CONTAINER]

                                  # docker exec

                                  # 1、进入容器内部调试

                                  基本语法：

                                  docker exec [OPTIONS] CONTAINER COMMAND [ARG...]

                                  这里的 CONTAINER 是容器的 ID 或名称，COMMAND 是你想在容器内执行的命令，而 ARG... 是传递给该命令的任何参数。

                                  # 了解docker网络模式

                                  Docker 提供了多种网络模式来管理容器之间以及容器与外部世界的通信。

                                  # bridge 网络模式

                                  • 概念：Bridge 是 Docker 的默认网络模式。当您运行一个容器时，它会自动连接到一个私有内部网络，这个网络通过一个名为 docker0 的网络桥接器在主机上创建。
                                  • 特点：
                                    • 每个运行在 bridge 网络上的容器都会获得自己的 IP 地址。
                                    • 容器之间可以互相通信，也可以通过网络端口映射与外部世界通信。
                                    • 提供了网络隔离。
                                  • 应用场景：适用于标准的容器应用，需要与外部世界进行有限交互的情况。

                                  # host 网络模式

                                  • 概念：在 host 模式下，容器共享宿主机的网络命名空间。
                                  • 特点：
                                    • 容器不会获得自己的 IP 地址，而是直接使用宿主机的 IP 和网络端口。
                                    • 容器可以直接访问外部网络，无需进行端口映射。
                                    • 性能较 bridge 模式有所提高，因为避免了网络转发的开销。
                                  • 应用场景：适用于需要高性能或避免网络隔离的场景，例如高性能的 Web 服务器。

                                  # none 网络模式

                                  • 概念：在 none 模式下，容器有自己的网络栈，但不会配置任何网络接口。
                                  • 特点：
                                    • 容器没有分配任何 IP，也不能与任何网络通信。
                                    • 提供了最大程度的网络隔离。
                                  • 应用场景：适用于不需要网络连接的任务，或者在特定的、完全控制的环境中运行的容器。

                                  # container 网络模式

                                  • 概念：在 container 模式下，一个新容器会共享另一个已经存在容器的网络栈。
                                  • 特点：
                                    • 新容器将与它共享网络栈的容器在网络上表现得完全一样。
                                    • 可以用来创建一组紧密关联的容器，它们在网络上表现为单一实体。
                                  • 应用场景：适用于需要将多个容器打包成单一服务的情况，例如一组紧密协作的微服务。

                                  # 了解底层Linux机制

                                  # namespace

                                  • 概念：Namespace 是 Linux 提供的一种机制，用于隔离和分割内核资源，使得每个进程只能看到自己的资源视图。它们为运行在容器内的进程提供了一种隔离的环境。
                                  • 关键特性：
                                    • PID Namespace：隔离进程ID。每个容器都有自己的 PID 空间，这意味着容器内的第一个进程可以被视为 PID 为 1 的进程，而在容器外部，它将有一个不同的 PID。
                                    • Network Namespace：隔离网络接口和配置。每个容器可以有自己的网络栈，包括 IP 地址、路由表、端口号等。
                                    • Mount Namespace：隔离文件系统挂载点。每个容器可以有自己的文件系统，与其他容器或主机系统隔离。
                                    • IPC Namespace：隔离进程间通信资源，确保容器内的进程只能看到同一命名空间内的 IPC 资源。
                                    • UTS Namespace：隔离主机名和域名，允许每个容器拥有自己的主机名和 NIS 域名。
                                    • User Namespace：隔离用户 ID，允许容器内的进程以不同的用户 ID 运行，增强了安全性。

                                  # cgroup

                                  • 概念：Cgroup 是 Linux 内核提供的另一种机制，用于限制、记录和隔离进程组所使用的物理资源（如 CPU、内存、磁盘 I/O 等）。
                                  • 关键特性：
                                    • 资源限制：可以限制容器可以使用的资源量，如 CPU 时间、系统内存、网络带宽或磁盘 I/O。
                                    • 优先级分配：可以控制各个容器对资源的使用优先级，以确保关键任务的性能。
                                    • 资源监控：可以监控容器使用的资源量，用于报告和计费。
                                    • 资源隔离：确保一个容器的资源使用不会影响到其他容器。

                                  # K8S（Kubernetes）基本概念

                                  # 了解k8s的功能，与docker的区别

                                  # docker应用容器引擎，单个容器管理

                                  • 基本概念：Docker 是一个应用容器引擎，用于容器化应用程序。它允许开发者将应用及其依赖打包到一个轻量级、可移植的容器中，然后在任何支持 Docker 的环境中运行。
                                  • 核心功能：
                                    • 容器管理：创建、运行、停止、移动和删除容器。
                                    • 镜像管理：构建、存储和分发应用程序的容器镜像。
                                    • 隔离性和安全：利用 Linux 的 namespace 和 cgroup 实现资源隔离和安全性。
                                  • 使用场景：适用于简化应用部署、提高环境一致性、实现微服务架构等。

                                  # k8s容器编排系统，分布式容器集群的管理

                                  • 基本概念：Kubernetes 是一个开源的容器编排系统，用于自动化容器化应用程序的部署、扩展和管理。它是一个分布式系统，支持跨多个主机的容器部署。
                                  • 核心功能：
                                    • 服务发现和负载均衡：Kubernetes 可以自动分配 IP 地址和一个 DNS 名给容器集群，可以在容器之间进行负载均衡。
                                    • 存储编排：自动挂载存储系统，如本地存储、公共云提供商等。
                                    • 自动部署和回滚：支持应用的自动部署和回滚。
                                    • 自动扩展：根据资源使用情况自动扩展或收缩应用。
                                    • 容器编排：在多个容器间进行自动分配和调度。
                                    • 自我修复：重启失败的容器、替换和重新调度容器到健康的节点、杀死不响应用户定义的健康检查的容器。
                                  • 使用场景：适用于大规模的容器部署、复杂应用的管理、实现高可用性和可扩展性。

                                  # Docker 与 Kubernetes 的区别

                                  • 管理层级：Docker 更侧重于单个容器的生命周期管理，而 Kubernetes 侧重于容器集群的管理。
                                  • 功能范围：Docker 是一个容器平台，提供了创建和运行容器的基本框架。Kubernetes 是一个更高级别的系统，用于编排由多个容器组成的复杂应用。
                                  • 设计目标：Docker 的设计目标是简化容器的创建和管理，而 Kubernetes 的设计目标是自动化部署、扩展和运行应用程序容器的整个生命周期。

                                  # 了解声明式API，不可变基础设施

                                  在软件和系统架构中，声明式 API 是指一种编程范式，它强调描述要做什么，而不是描述如何做。这种方法与命令式编程形成对比，后者则更侧重于具体的操作步骤和逻辑流程。

                                  • 特点：
                                    • 高层次的抽象：用户仅需声明所需的最终状态或结果，而不需要关心实现细节。
                                    • 简化管理：系统或框架负责理解这些声明并确定如何实现这些目标。
                                    • 易于理解和维护：由于用户不需要处理底层逻辑，代码通常更加简洁和易于维护。
                                  • 应用场景：在云计算和容器编排系统（如 Kubernetes）中非常常见。例如，在 Kubernetes 中，您可以声明一个 Deployment，指定所需的副本数量和容器配置，而 Kubernetes 会处理实际的容器部署和调度。

                                  不可变基础设施

                                  不可变基础设施是一种系统管理策略，其中服务器和其他基础设施组件一旦部署，就不再被修改。如果需要更改或更新，系统管理员会替换整个服务器或组件，而不是在原有实例上进行修改。

                                  • 特点：
                                    • 稳定性和一致性：由于系统组件不会被修改，因此可以避免由配置更改引起的问题。
                                    • 可预测性：每次部署都是从预定义的配置开始，确保了环境之间的一致性。
                                    • 简化回滚：如果更新有问题，可以快速回滚到之前的状态，因为旧的配置仍然存在。
                                    • 自动化和标准化：通常与自动化工具结合使用，以标准化部署和管理过程。
                                  • 应用场景：广泛应用于云计算和现代 DevOps 实践。例如，使用容器和微服务架构时，通常采用不可变基础设施的原则。

                                  # 了解k8s整体架构和组件

                                  # 控制面

                                  控制面的组件负责整个集群的全局决策（例如调度），以及检测和响应集群事件（例如，当一个部署的副本数不足时，启动新的容器）。

                                  # 1、APIService
                                  • 作用：APIService 提供了一个扩展 Kubernetes API 的方式。它允许你将自定义的 API 服务与 Kubernetes API 服务器集成。这对于添加新的功能和资源类型到您的集群非常有用。
                                  # 2、Controller Manager
                                  • 作用：它运行控制器进程。
                                  • 细节：
                                    • 每个控制器都是一个独立的进程，但为了减少复杂性，它们都被编译成一个单独的可执行文件，并在同一个进程中运行。
                                    • 这些控制器包括节点控制器、复制控制器、端点控制器、服务帐户和令牌控制器等。
                                  # 3、Scheduler
                                  • 作用：调度器监视尚未分配到节点上的新创建的 Pod，并选择一个节点供它们运行。
                                  • 细节：
                                    • 调度决策考虑到的因素包括个别和集体资源需求、硬件/软件/策略限制、亲和性和反亲和性规范、数据局部性、工作量间的干扰和截止日期。
                                  # 4、Etcd
                                  • 作用：Etcd 是一个轻量级、分布式的键值存储系统，用于存储所有集群数据，确保数据的一致性。
                                  • 细节：
                                    • Kubernetes 使用 etcd 来存储全局配置数据，可以被集群中的每个节点所访问。
                                    • 它存储了整个 Kubernetes 的状态，作为集群的“真实来源”。

                                  # 节点

                                  # 1、kubelet
                                  • 作用：kubelet 是在 Kubernetes 集群的每个节点上运行的主要“节点代理”。它负责确保容器在 Pod 中运行，并且这些容器是用户提交给 Kubernetes 的规格的一部分。
                                  • 功能：
                                    • 监听来自控制面的指令和信息，并确保容器在 Pod 中健康运行。
                                    • 管理 Pod 的生命周期，包括创建、修改和删除。
                                    • 根据 PodSpecs（YAML 或 JSON 格式的文件，描述了 Pod 应该是什么样的），自动部署和管理容器。
                                    • 上报节点状态和监测到控制面。
                                  • 运行方式：kubelet 与容器运行时（如 Docker）和 etcd 进行交互，管理本地的容器。
                                  # 2、kube-proxy
                                  • 作用：kube-proxy 是 Kubernetes 服务的网络代理，运行在每个节点上。它维护节点上的网络规则，这些规则允许网络通信到您的 Pod 从集群内部或外部发起。
                                  • 功能：
                                    • 管理节点上的网络规则，如 IP 转发和 NAT 表，以允许网络通信到 Pods。
                                    • 实现部分或全部的服务发现和负载平衡功能，例如，它可以平衡负载到后端 Pod。
                                    • 可以以用户空间模式、iptables 模式或 IPVS 模式运行，不同的模式决定了它如何实现服务抽象。
                                  • 运行方式：kube-proxy 使得 Kubernetes 服务的网络抽象成为可能，并且可以随着集群规模的扩大而自动进行扩展。

                                  # 熟悉常用资源

                                  # namespace

                                  • 作用：Namespace 是一种将集群资源划分为多个独立的部分的方法。它们用于在逻辑上分隔集群，使其能够支持多个用户、团队或项目。
                                  • 特点：
                                    • 常用于多租户环境，为不同的用户或团队提供隔离的环境。
                                    • 可以用于资源配额和访问控制，限制用户可以使用的资源量和访问的资源类型。

                                  # deployment

                                  • 作用：Deployment 用于声明式地更新 Pods 和 ReplicaSets。它主要用于无状态应用的部署和扩展。
                                  • 特点：
                                    • 提供声明式的更新能力，如滚动更新、版本回滚等。
                                    • 保证应用的副本数（Pods 的数量）始终符合用户定义的期望状态。
                                    • 通常与 Service 结合使用，以实现负载均衡和服务发现。

                                  # pod

                                  • 作用：Pod 是 Kubernetes 中可部署的最小单位，它是一个或多个容器的组合。
                                  • 特点：
                                    • Pod 中的容器共享存储、网络和其他资源配置。
                                    • 用于运行单个实例的应用或服务。
                                    • Pod 是临时的，由 Kubernetes 自动管理其生命周期。

                                  # service

                                  • 作用：Service 是定义一组逻辑上相关联的 Pod 访问规则的抽象层。它允许外部访问 Pod 组或在 Pod 组之间进行通信。
                                  • 特点：
                                    • 提供稳定的 IP 地址和端口号，即使背后的 Pod 发生变化。
                                    • 支持负载均衡和服务发现。
                                    • 类型包括 ClusterIP、NodePort 和 LoadBalancer。

                                  # ingress

                                  • 作用：Ingress 是对外部访问集群服务的管理，通常提供 HTTP 和 HTTPS 路由。
                                  • 特点：
                                    • 可以提供 URL 路由、负载均衡、SSL 终端和名称基础的虚拟托管。
                                    • 一种集中管理访问策略的方式，适用于复杂的路由需求。

                                  # kuberctl 命令的基本使用

                                  # kuberctl create

                                  这个命令用于在 Kubernetes 集群中创建一个或多个资源。可以使用文件（通常是 YAML 或 JSON 格式）或直接在命令行指定参数来创建资源。

                                  # 1、资源的创建

                                  • 使用 YAML 或 JSON 文件创建资源：

                                    • 命令格式：

                                      kubectl create -f [filename]

                                    • 示例：

                                      kubectl create -f my-resource.yaml

                                  这会根据 my-resource.yaml 文件中定义的内容创建一个或多个 Kubernetes 资源。

                                  • 直接在命令行创建特定资源：

                                    • 创建命名空间（Namespace）：

                                      kubectl create namespace [namespace-name]

                                    • 创建部署（Deployment）：

                                      kubectl create deployment [deployment-name] --image=[image-name]

                                  • 创建服务（Service）：

                                    kubectl create service clusterip [service-name] --tcp=5678:8080

                                  注意事项

                                  • 确保在运行 kubectl create 命令之前已经配置了对 Kubernetes 集群的访问。这通常涉及设置 kubeconfig 文件，该文件包含集群访问信息。
                                  • 使用 -f 标志和文件创建资源时，文件中的资源定义必须是有效的 YAML 或 JSON 格式。
                                  • 直接在命令行创建资源时，需要指定足够的参数来定义资源。例如，创建部署时需要指定部署名称和应用的容器镜像。

                                  # kuberctl describe

                                  于显示 Kubernetes 资源的详细信息。这个命令非常有用，特别是当需要了解资源的当前状态、相关的配置详情以及系统中发生的事件时。

                                  # 1、查看资源详细信息

                                  • 通用命令格式：

                                    kubectl describe [resource-type] [resource-name]

                                    • 其中 [resource-type] 是资源类型，例如 pod, service, deployment 等。

                                    • [resource-name] 是资源的具体名称。如果省略资源名称，此命令将显示该类型所有资源的详细信息。

                                  • 示例：

                                    • 查看特定 Pod 的详细信息：

                                      kubectl describe pod my-pod

                                    • 查看某个 Deployment 的详细信息：

                                      kubectl describe deployment my-deployment

                                    • 查看所有服务（Service）的详细信息：

                                      kubectl describe services

                                    • 查看特定命名空间的详细信息：

                                      kubectl describe namespace my-namespace

                                  注意事项

                                  • 在使用 kubectl describe 命令时，确保您已经配置了对 Kubernetes 集群的访问。
                                  • kubectl describe 提供的信息非常全面，包括资源的元数据、规格（spec）、状态（status）以及系统生成的事件日志。
                                  • 这个命令对于故障排查和系统监控特别有用，因为它不仅显示了资源的当前状态，还包括了 Kubernetes 系统关于该资源的最近操作和事件。

                                  # kuberctl exec

                                  用于在正在运行的容器中执行命令。这个命令特别有用于调试和故障排除，因为它允许用户直接访问容器的运行环境。

                                  # 1、常用于进入容器内部调试

                                  • 执行容器中的命令：

                                    • 基本命令格式是：

                                      kubectl exec [POD_NAME] -- [COMMAND]

                                    • 例如，在名为 my-pod 的 Pod 的容器中执行 ls

                                      命令：

                                      kubectl exec my-pod -- ls

                                  • 交互式进入容器：

                                    • 如果你想交互式地进入容器（例如，启动一个 shell），可以使用 -it

                                      例如：

                                      kubectl exec -it [POD_NAME] -- /bin/bash

                                    • 这个命令会启动一个 bash shell（如果容器中有 bash 的话）在指定的 Pod 中。例如：

                                      kubectl exec -it my-pod -- /bin/bash

                                  注意事项

                                  • 确保你指定的 Pod 名称和容器中要执行的命令是正确的。
                                  • 如果 Pod 中有多个容器，你需要使用 -c 参数来指定容器名称。
                                  • 使用 kubectl exec 进行调试时，请小心操作，以免破坏容器内的环境。
                                  • 交互式进入容器对于快速检查应用状态、查看日志文件、故障排除等非常有用。

                                  # kuberctl edit

                                  通过这个命令，可以对资源的 YAML 定义进行修改，从而更新资源的状态和配置。这是一种快速调整资源设置的方法，尤其适用于调试和临时更改。

                                  # 1、编辑资源定义的yaml文件

                                  • 基本用法：

                                    • 命令格式：

                                      kubectl edit [resource-type] [resource-name]

                                    • 其中 [resource-type] 是资源类型（如 pod, service, deployment 等），[resource-name] 是要编辑的资源的名称。

                                  • 示例：

                                    • 编辑一个名为 my-deployment 的 Deployment：

                                      kubectl edit deployment my-deployment

                                  • 编辑一个名为 my-service 的 Service：

                                    kubectl edit service my-service

                                  注意事项

                                  • 当运行 kubectl edit 命令时，会自动打开系统默认的文本编辑器，通常是 Vim 或 Nano，取决于你的环境变量设置。
                                  • 在编辑器中对 YAML 文件进行修改后，保存并关闭编辑器会使更改生效。Kubernetes 将尝试根据你的修改更新资源。
                                  • 如果你的更改无效或有语法错误，Kubernetes 将拒绝应用这些更改，并且通常会在命令行输出错误信息。
                                  • 请小心使用 kubectl edit，因为直接修改资源可能会导致不可预见的结果，特别是在生产环境中。
