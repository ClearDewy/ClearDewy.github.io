# 推理、评测与安全

权重训练完成并不等于系统可用。推理把概率分布转化为输出；评测判断输出是否满足目标；安全控制失效时的影响范围。

## 1. 从 logits 到输出

- greedy 每步选择最大概率，稳定但可能重复或局部最优；
- temperature 调整分布尖锐程度；
- top-k 只保留概率最高的 k 个候选；
- top-p 保留累计概率达到阈值的最小候选集合；
- beam search 保留多个高分序列，适合目标较明确的生成。

采样参数改变的是输出分布，不能修复模型没有学到的知识。

## 2. 推理性能

Prefill 并行处理输入，decode 通常逐 token 进行。KV Cache 避免重复计算历史 K/V，但内存随层数、序列、batch、KV 头数和精度增长。

量化、continuous batching、paged cache、speculative decoding 和编译分别作用于权重表示、调度、内存、生成步骤和算子执行。优化必须同时验证输出变化、延迟、吞吐、显存和硬件条件。

## 3. 评测分层

| 层级 | 典型证据 | 不能单独证明 |
| --- | --- | --- |
| 单元/不变量 | shape、mask、梯度、序列化测试 | 任务能力 |
| 模型离线评测 | loss、准确率、基准集 | 真实用户价值 |
| 系统离线评测 | 检索、工具、端到端任务成功率 | 线上分布稳定 |
| 小流量在线评测 | 行为、反馈、延迟和成本 | 长期无漂移 |
| 运行监控 | 真实流量趋势和事件 | 因果改进来源 |

基准必须版本化，并检查污染、样本代表性、评分器偏差和统计不确定性。人工评审要有清晰 rubric、盲评和一致性检查。

## 4. 错误分类

把失败至少区分为：输入理解、知识缺失、推理过程、格式/指令、检索、工具、权限、超时和评分错误。只有分类后，才能决定应该改数据、模型、prompt、检索、工具还是控制流程。

## 5. 安全边界

- 模型安全：有害内容、偏见、隐私记忆和越狱；
- 应用安全：提示注入、数据外泄、越权工具与供应链内容；
- 运行安全：资源耗尽、重试风暴、错误自动化和不可逆操作；
- 治理：数据许可、审计、人工责任和事件响应。

高风险动作需要最小权限、结构化校验、隔离环境、人工审批和可追溯记录，不能只依赖模型自我约束。

## 6. 本章实践

建立一个固定小评测集和结果格式；比较两个模型或两个采样配置，报告均值、逐类错误、延迟和成本。随后加入一个对抗输入集，验证系统边界是否真实生效。
