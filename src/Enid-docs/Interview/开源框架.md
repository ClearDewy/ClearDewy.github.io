#### 阅读gin源码，了解middleware的实现原理

中间件在 Gin 中是一种特殊类型的函数，它可以访问和操作请求和响应。每个中间件可以执行以下操作：

- 在调用路由处理函数之前执行某些任务。
- 在调用路由处理函数之后执行某些任务。
- 修改请求和响应。
- 决定是否继续执行请求链。

Middleware是Gin 框架中中间件。

**Gin 中间件的实现原理**

- **函数签名**：

  Gin 中的中间件是一个遵循特定签名的函数，即接收一个 *gin.Context 对象并返回无。

  ```go
  func MyMiddleware(c *gin.Context) {
      // 中间件逻辑
  }
  ```

- **请求处理链**：

  在 Gin 中，请求通过一系列的中间件和最终的路由处理函数传递。这些组成了一个“处理链”。

- **\*gin.Context 对象**：

  每个中间件和路由处理函数都接收一个 *gin.Context 对象，它包含了请求的详细信息和用于发送响应的工具。

- **执行流程**：

  - 当一个请求到达时，Gin 会按照中间件注册的顺序执行它们。

  - 通过调用 c.Next()，中间件可以将控制权传递给链中的下一个处理程序。

  - 如果中间件没有调用 c.Next()，则处理链将停止，后续的中间件和路由处理函数将不会被执行。

**实例**

请求处理前后打印一条日志，展示处理请求所花费的时间

```go
func LoggerMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        // 请求前
        t := time.Now()

        // 处理请求
        c.Next()

        // 请求后
        latency := time.Since(t)
        fmt.Printf("请求处理时间: %v\n", latency)
    }
}
```

```go
func main() {
    r := gin.Default()

    // 应用中间件
    r.Use(LoggerMiddleware())

    // 定义一个路由
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(200, gin.H{
            "message": "pong",
        })
    })

    // 运行服务
    r.Run() // 默认监听并在 0.0.0.0:8080 上启动服务
}
```

## rpc框架

### grpc

#### 掌握proto语法，熟练使用grpc开发rpc接口

#### 了解grpc resolver服务发现实现机制

gRPC 的 Resolver 是一种服务发现机制，用于抽象化服务端点的发现和解析。这使得客户端能够透明地连接到由服务发现系统提供的多个后端服务实例。在分布式和微服务架构中，这个功能尤其重要，因为它支持负载均衡、故障转移和服务动态发现等功能。

**工作原理**

- **服务发现**：

  Resolver 负责将服务名解析为一组后端服务器的地址。它可以与各种服务发现系统（如 Consul、Etcd、Zookeeper、DNS 等）集成，以动态地获取服务的最新地址。

- **更新地址列表**：

  Resolver 定期或在发生变化时更新后端服务器的地址列表。这确保了客户端总是连接到可用的服务实例。

- **负载均衡**：

  Resolver 与 gRPC 的负载均衡器（Load Balancer）紧密集成。负载均衡器使用 Resolver 提供的地址列表来分配请求，实现负载均衡。

- **连接管理**：

  Resolver 还负责帮助管理客户端与后端服务之间的连接。当服务实例变更时，它会通知负载均衡器，后者可以相应地调整连接。

#### 了解grpc interceptor的原理

gRPC Interceptor 是 gRPC 框架中的一个重要特性，用于在 RPC 调用的处理流程中插入自定义逻辑。它类似于其他编程框架中的中间件或过滤器，允许开发者在请求被实际处理之前或之后执行某些操作。gRPC Interceptor 可以分为客户端拦截器和服务端拦截器。

**实现原理**

gRPC Interceptor 的实现基于装饰器模式，允许你封装和修改 RPC 调用的行为。

- **链式调用**：多个拦截器可以形成一个链，按顺序执行。每个拦截器可以决定是否调用链中的下一个拦截器，或直接返回响应。
- **Context 传递**：拦截器可以通过 Context 传递额外的信息，这对于在拦截器链中共享数据非常有用。

##### 1、使用场景

**客户端拦截器**

- **日志记录**：在发送请求和接收响应时记录日志，有助于调试和监控。

- **身份验证和授权**：在每个请求中添加身份验证令牌或执行授权逻辑。

- **请求重试和故障转移**：在请求失败时自动重试，或将请求重定向到另一个服务实例。

- **请求/响应转换**：修改或转换出站请求和入站响应的数据。

**服务端拦截器**

- **访问控制**：检查用户的身份验证信息和授权，确保安全性。

- **监控和度量**：收集关于请求的度量数据，例如处理时间、请求大小等。

- **日志和审计**：记录关于请求的日志信息，用于审计和后续分析。

- **预处理和后处理**：在业务逻辑执行前后进行一些通用处理，如验证请求参数、格式化响应等。

**示例**

一个简单的服务端拦截器，它在处理 RPC 请求前后打印日志

```go
func LoggingInterceptor(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (interface{}, error) {
    // 在处理请求前记录日志
    log.Printf("接收到请求: %s", info.FullMethod)
    // 调用实际的 RPC 方法
    resp, err := handler(ctx, req)
    // 在处理请求后记录日志
    log.Printf("请求完成: %s", info.FullMethod)
    return resp, err
}

// 在 gRPC 服务器中注册拦截器
grpc.NewServer(grpc.UnaryInterceptor(LoggingInterceptor))
```

- **SQL builder**

  SQL 构建器允许你以编程方式构建 SQL 语句，而不是手动拼接字符串。这样做的好处是更安全（防止 SQL 注入）、更易维护和可读。

  ```go
  type Product struct {
      gorm.Model
      Code  string
      Price uint
  }
  
  // 查询
  var products []Product
  db.Where("price > ?", 100).Find(&products)
  
  // 复杂查询
  db.Where("price > ? AND code = ?", 100, "D42").Find(&products)
  ```

  Where 方法是一个 SQL 构建器，它帮助构建条件查询

- **CURD**

- **事务处理**

  事务是确保数据库操作原子性的一种机制。在事务中，一系列操作要么全部成功，要么全部失败。

  ```go
  // 开始事务
  tx := db.Begin()
  
  // 执行一些数据库操作
  result=tx.Create(&Product{Code: "D43", Price: 200})
  
  // 如果出错，则回滚事务
  if result.Error != nil {
      tx.Rollback()
      return
  }
  
  // 否则，提交事务
  tx.Commit()
  ```

#### 学习gorm自定义callback 的设计思路

Gorm 的回调（Callback）机制允许开发者在数据库操作的不同阶段插入自定义的逻辑。

- **何时使用 Callbacks**：

  当你需要在 CRUD 操作（创建、读取、更新、删除）之前或之后执行特定逻辑时。例如，在保存记录之前自动设置或更新字段、在读取后进行数据转换等。

- **Callback 的种类**：

  Gorm 提供了多种回调，如 BeforeCreate、AfterCreate、BeforeUpdate、AfterUpdate、BeforeDelete、AfterDelete、AfterFind 等。

**设计思路和步骤**

a. **确定回调时机**

首先，根据需求确定你需要在哪个操作阶段添加自定义逻辑。是在创建记录之前？还是在查询之后？这将决定使用的是 BeforeCreate、AfterFind 或其他回调。

b. **注册自定义回调**

使用 Gorm 的 Callback() 方法注册你的自定义回调函数。确保你的回调函数符合预期的签名。

```go
func (p *Product) BeforeCreate(tx *gorm.DB) (err error) {
    if p.Code == "" {
        err = errors.New("code cannot be empty")
        return
    }
    // 自定义逻辑...
    return
}

// 在初始化 Gorm 时注册回调
db.Callback().Create().Before("gorm:create").Register("my_before_create_hook", &Product{})
```

在这个例子中，我们定义了一个在创建 Product 之前执行的回调，用于检查 Code 字段是否为空。

.Create().Before("gorm:create") 指定了回调的类型是在创建操作（Create）之前的某个点。Gorm 会在 Product 结构体中查找与此类型匹配的方法。在你的 Product 结构体中，如果有一个符合回调签名的 BeforeCreate 方法，Gorm 就会在创建操作之前自动调用这个方法。

c. **考虑回调的顺序**

Gorm 允许你指定回调的执行顺序。你可以通过在注册时指定 Before 或 After 来决定自定义回调相对于内置回调的执行顺序。

d. **处理错误和中断**

在你的自定义回调中，你可以返回错误。如果回调返回错误，Gorm 将中断当前操作并回滚事务（如果在事务中）。

e. **灵活使用上下文（Context）**

你的自定义回调可以根据当前的 *gorm.DB 上下文来执行操作，这意味着你可以访问关于当前操作的信息，甚至修改它。

### dubbo-go

#### 了解Dubbo-Go的基本概念和核心组件

Dubbo-Go 是 Apache Dubbo（一个高性能、轻量级的开源 Java RPC 框架）的 Go 语言实现版本。它旨在为 Go 语言提供高性能和透明化的 RPC 远程服务调用。与 Java 版本的 Dubbo 类似，Dubbo-Go 专注于提供高效的通信机制和丰富的服务治理特性。

**基本概念**

- **RPC（Remote Procedure Call）**：

  远程过程调用，允许程序调用另一台计算机上的程序，就像调用本地程序一样。

- **服务提供者（Provider）**：

  提供远程服务的应用程序。它将服务注册到注册中心，并等待消费者调用。

- **服务消费者（Consumer）**：

  调用远程服务的应用程序。它从注册中心订阅服务，并进行远程调用。

- **注册中心（Registry）**：

## CI/CD

持续集成（Continuous Integration，简称 CI）和持续部署（Continuous Deployment，简称 CD）是现代软件开发中的两个核心实践，通常一起提到，简称 CI/CD。它们是实现敏捷开发和 DevOps 的关键组件，旨在提高软件开发和交付的速度与质量。

### 持续集成（CI）

持续集成是一种软件开发实践，其中开发人员定期将他们的代码更改合并到主分支中。每次代码合并时，自动执行构建和测试，以确保这些更改不会破坏现有系统。

#### CI 的关键特点：

- **自动化构建和测试**：对每次提交到版本控制系统的代码进行自动化构建和测试。

- **快速反馈**：如果构建或测试失败，立即通知开发团队，使他们能够快速响应和修复问题。

- **代码库维护**：保持代码库始终处于可部署状态。

### 持续部署（CD）

持续部署是 CI 的延伸，它不仅涉及自动化测试，还包括自动化将代码从仓库部署到生产环境的过程。

#### CD 的关键特点：

- **自动化部署**：在代码通过所有测试后，自动将其部署到生产环境。

- **快速发布**：使新功能和修复更快地到达最终用户。

- **减少人为错误**：通过自动化流程减少部署过程中的人为错误。

### CI/CD 流程

a.**代码提交**：开发者提交代码到版本控制系统（如 Git）。

b.**自动化构建**：CI 工具（如 Jenkins、Travis CI）自动构建系统。

c.**自动化测试**：运行一系列自动化测试，确保代码的质量。

d.**部署**：如果代码通过所有测试，CD 工具将代码自动部署到生产环境。

e.**监控和反馈**：对生产环境进行监控，收集反馈，用于未来的迭代。

### 工具和平台

流行的 CI/CD 工具和平台包括：

- **Jenkins**：一个开源的自动化服务器，可以用来自动化各种任务，包括构建、测试和部署软件。
- **Travis CI、CircleCI**：云基础的 CI/CD 服务，用于自动化测试和部署。
- **GitLab CI/CD**：GitLab 提供的集成 CI/CD 解决方案。
- **GitHub Actions**：GitHub 提供的用于自动化工作流程的平台。
