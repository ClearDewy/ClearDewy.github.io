- **错误检查和Linting**：集成了诸如 golint、govet 等工具，能够在编写代码时实时检查错误和潜在问题。

- **文档查看**：允许用户在不离开 Vim 的情况下查看 Go 文档。

- **代码片段支持**：支持代码片段插入，提高编码效率。

- **依赖管理**：支持 Go 依赖管理工具，如 go mod。

- **调试**：集成了对 Delve（Go 语言的调试器）的支持，允许在 Vim 中进行调试。

#### 项目配置Go

##### GOROOT

###### 1、sdk版本切换

- **手动切换**：

  你可以下载不同版本的 Go 并解压到不同的目录。然后根据需要修改 GOROOT 环境变量来指向不同版本的 Go 目录。这种方法比较简单，但需要手动修改环境变量。

- **使用版本管理工具**：

  使用像 gvm（Go Version Manager）这样的版本管理工具可以方便地切换不同版本的 Go。gvm 允许你安装多个版本的 Go，并且可以轻松地切换当前使用的版本。使用 gvm，你可以避免手动修改 GOROOT。

- **容器化开发环境**：

  在 Docker 容器中设置开发环境也是管理不同 Go 版本的一个有效方式。你可以为每个项目创建一个包含特定 Go 版本的容器。这种方法的优点是，它不仅管理 Go 的版本，还能够确保其他依赖项的一致性。

- **包管理工具**：

  在某些操作系统上，你可以使用包管理工具来安装和切换不同版本的 Go，例如在 macOS 上使用 brew。

##### GOPATH

###### 1、全局/项目PATH

- **全局 GOPATH**：

  在 Go Modules 出现之前，GOPATH 是全局设置的，通常指向用户主目录下的一个特定子目录，如 ~/go。它包含三个主要子目录：

  - src：包含 Go 的源代码（例如 .go 文件）。
  - pkg：包含包对象文件。
  - bin：包含编译后的可执行文件。

  所有 Go 项目都被放置在这个单一的工作空间内的 src 目录下。

- **项目级 GOPATH（在 Go Modules 出现后）**：

  Go 1.11 引入了 Go Modules，这是一种依赖管理系统，允许项目在任何地方被构建，而不仅仅是在 GOPATH 下。使用 Go Modules 后，你可以在项目目录外设置 GOPATH，而项目本身在其自己的目录中维护依赖（通常在 go.mod 和 go.sum 文件中）。这样，每个项目都可以有自己的依赖版本，这使得项目更加独立，更容易管理。

##### GOMODULES（推荐）

###### 1、开启模块集成，添加环境变量

- **开启 Go Modules**：

  从 Go 1.11 版本开始，你可以在任意目录下创建 Go 项目，并使用 Go Modules 进行依赖管理。要启用 Go Modules，可以设置环境变量 GO111MODULE。此环境变量有三个值：off（关闭 Go Modules 功能），on（强制使用 Go Modules），auto（在 GOPATH 外自动启用 Go Modules）。

  ```bash
  export GO111MODULE=on
  ```

- **初始化新模块**：

  在项目目录下运行以下命令来初始化一个新的模块。这将创建一个 go.mod 文件，其中包含模块的名称和当前使用的 Go 版本。

  ```bash
  go mod init [module-name]
  ```

- **添加依赖**：

  当你使用 go get 添加新的依赖时，这些依赖会自动添加到你的 go.mod 文件中。当你导入新的包并运行 go build 或 go test 时，这些依赖也会被自动添加。

- **管理依赖**：

  go.mod 文件声明了项目的依赖。你可以手动编辑这个文件，但通常建议通过 Go 命令来管理依赖。使用 go mod tidy 命令可以清理未使用的依赖，并更新 go.mod 文件。

- **兼容性和迁移**：

  Go Modules 设计用来与旧的 GOPATH 方式兼容。如果你有现有的项目在 GOPATH 下，你可以在项目根目录运行 go mod init 来迁移到 Go Modules。

- **版本控制**：

  go.mod 和 go.sum 文件应该被纳入版本控制。go.sum 文件包含每个依赖的期望加密校验和，用于确保项目依赖的完整性和一致性。

- **实现：**

##### File Watchers

File Watchers 是一种在文件发生更改时自动执行特定任务的工具。

###### 1、go fmt 格式化

- **功能**：go fmt 是 Go 语言的标准工具，用于自动格式化 Go 代码，使其符合 Go 的代码风格指南。
- **配置 File Watcher**：你可以在 File Watchers 中设置一个任务，以便在每次保存 Go 文件时自动运行 go fmt。
- **操作：**
  - 指定要监视的文件类型（如 *.go）。
  - 设置执行的命令为 go fmt。
  - 配置其他选项，如作用域和触发条件。

###### 2、goimports 引用包

- **功能**：goimports 是 go fmt 的超集，它不仅格式化代码，还自动添加缺失的包引用并删除未使用的包引用。
- **配置 File Watcher**：类似于 go fmt，你可以配置 File Watcher 在文件保存时运行 goimports。
- **操作：**
  - 同样指定要监视的文件类型（如 *.go）。
  - 设置执行的命令为 goimports。

###### 3、golangci-lint 静态检查

- **功能**：golangci-lint 是一个强大的静态代码分析器，它集成了多个 linters，用于检查 Go 代码中的错误、风格问题和潜在的 bugs。
- **配置 File Watcher**：配置 File Watcher 在文件保存时自动运行 golangci-lint，以确保代码质量。
- **操作：**
  - 设置要监视的文件类型。
  - 配置执行命令为 golangci-lint run。
  - 可以配置其他参数，如指定分析的范围或忽略特定警告。

**配置示例（在 IDE 中，如 IntelliJ IDEA 或 GoLand）**

a.打开设置或首选项，找到 File Watchers。

b.创建新的 File Watcher，选择 Go 文件类型。

c.配置执行的命令和参数。例如，对于 go fmt，命令是 go，参数是 fmt。

d.保存并应用更改。

## 静态代码检查

### golangci-lint

golangci-lint 是一个流行的 Go 语言静态分析工具，它聚合了多种 linters，可以帮助检测代码中的错误、不一致的编码风格、未使用的代码等问题。它被广泛用于提高 Go 代码质量和一致性。

#### 命令

##### 1、golangci-lint run [目录]/[文件]

**基本用法**：

- golangci-lint run：在当前目录及其所有子目录中运行 linters。
- golangci-lint run [文件或目录]：指定特定文件或目录来运行 linters。

#### 配置文件

##### 1、.golangci.yaml

.golangci.yaml（或 .golangci.yml）是 golangci-lint 工具的配置文件，它允许你定制 golangci-lint 的行为，包括启用或禁用特定的 linters、设置其各种参数和规则等。这个文件通常位于项目的根目录中。

- **启用或禁用 linters**：指定要在代码检查中使用的 linters，或者明确禁用某些 linters。

  ```yaml
  linters:
    enable:  #代码检查中启用的 linters
      - govet
      - golint
    disable:  #显式禁用的 linters
      - errcheck
  ```

- **设置 linters 参数**：为特定的 linters 设置参数或规则。

  ```yaml
  linters-settings:
    govet:
      check-shadowing: true  #启用 govet 的变量遮蔽检查功能。变量遮蔽是指在一个作用域中重新声明一个在外层作用域中已声明的变量
    golint:
      min-confidence: 0.8  #调整 golint 的置信度阈值。只有当 golint 认为代码问题的置信度超过 0.8 时，才会报告该问题
  ```

- **排除文件或目录**：指定不应由 linters 检查的文件或目录。

  ```yaml
  issues:
    exclude-rules:  #定义了一系列排除规则
      - path: _test\.go  #所有以 _test.go 结尾的文件（即测试文件），golint 的检查将被忽略
        linters:
          - golint
  ```

- **运行设置**：配置 golangci-lint 的一些运行参数，如并发数、超时设置等。

  ```yaml
  run:
    timeout: 5m  #设置 golangci-lint 运行的超时时间为 5 分钟
    concurrency: 4  #使用的并发数为 4
  ```

#### 常用配置项

##### 1、typecheck/govet/varcheck/deadcode/errcheck/structcheck/unused/go simple

- **typecheck**：

  一个基本的 linter，用于进行类型检查，确保变量和函数调用等的类型正确。

- **govet**：

  govet 是 Go 语言自带的 linter，用于检查可能的错误、可疑构造、代码简化等。它涵盖了从代码正确性到风格问题的广泛检查。

- **varcheck**：

  varcheck 用于检查未使用的全局变量。对于大型项目中清理无用代码很有帮助。

- **deadcode**：

  deadcode 用于检测未被使用的代码，如未调用的函数和方法。

- **errcheck**：

  errcheck 用于检查未处理的错误。在 Go 中，忽略错误处理可能会导致难以追踪的问题。

- **structcheck**：

  structcheck 用于发现未使用的 struct 字段，有助于优化数据结构。

- **unused**：

  unused 会检查未使用的代码，包括变量、常量、函数、类型等。

- **gosimple**：

  gosimple 专注于简化 Go 代码。它会提示替换复杂结构的简单方法。

### pre-commit

pre-commit 是一个用于管理和维护多个预提交钩子的工具。它允许你配置一系列的钩子，这些钩子会在你提交代码到版本控制系统之前自动运行。这些钩子通常用于代码格式化、lint检查、单元测试等，有助于保证代码质量和风格的一致性。

#### 命令

##### 1、pre-commit run --all-files（运行检查）

是一个用于手动运行所有配置的预提交钩子的命令，无论文件是否被 Git 暂存（staged）。

- **用途**：
  - **运行所有钩子**：这个命令会运行 .pre-commit-config.yaml 文件中定义的所有钩子，对项目中的所有文件进行检查。
  - **检查整个项目**：即使你没有对文件进行更改或文件未被暂存，这个命令也会检查整个项目。这在确定现有代码库是否符合新加入的钩子规则时非常有用。
- **适用场景**：
  - 当你想确保整个代码库符合预提交钩子的要求时。
  - 在添加新的钩子或修改现有钩子配置后，检查整个项目。
  - 作为 CI/CD 流程的一部分，以确保所有代码在提交之前都经过了相同的检查。

##### 2、pre-commit init-templatedir（初始化模板）

用于初始化一个 git 钩子模板目录。这个命令的作用是将 pre-commit 钩子的配置复制到 git 的模板目录中，使得新创建的 git 仓库自动包含这些钩子配置。

- **命令格式**：pre-commit init-templatedir [模板目录路径]
- **功能：**
  - 将 pre-commit 配置的钩子脚本安装到指定的 git 钩子模板目录中。
  - 当创建新的 git 仓库或在现有仓库中运行 git init 时，这些钩子将自动被添加到仓库的 .git/hooks 目录下。

- **使用场景和好处**

  - **自动化设置**：对于经常需要在多个项目中使用相同的钩子配置的开发团队或个人来说，这个命令非常有用。它省去了在每个新项目中手动设置钩子的步骤。

  - **保持一致性**：确保所有新创建的仓库自动包含团队标准的钩子，从而保持代码质量和风格的一致性。

- **使用示例**

假设你已经有了一个包含 pre-commit 配置的项目，并且想要将这些配置用作新项目的默认钩子设置，你可以这样做：

```bash
## 首先，找到一个放置 git 钩子模板的地方，如 ~/git-templates
mkdir -p ~/git-templates

## 使用 pre-commit init-templatedir 命令初始化这个目录
pre-commit init-templatedir ~/git-templates

## 配置 git 使用这个模板目录
git config --global init.templateDir ~/git-templates
```

执行这些步骤后，每当你运行 git init 初始化一个新的 git 仓库时，pre-commit 的钩子就会自动被添加到新仓库中。

#### 配置文件

##### 1、.pre-commit-config.yaml

.pre-commit-config.yaml 是用于配置 pre-commit 钩子的 YAML 文件。通过这个文件，你可以定义在提交代码到版本控制系统之前要自动执行的一系列钩子任务，如代码格式化、lint检查、单元测试等。这个文件通常位于项目的根目录。

```yaml
## 指定pre-commit的版本
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v3.4.0  ## 使用特定版本
    hooks:
      - id: trailing-whitespace  ## 钩子ID
        ## 其他可选配置项...

  - repo: https://github.com/psf/black
    rev: 21.7b0
    hooks:
      - id: black
        language_version: python3.8  ## 指定Python版本
        ## 其他可选配置项...

  ## 可以继续添加更多的钩子...
```

##### 重要的配置项

- **repos**：定义要使用的钩子仓库的列表。
  - **repo**：钩子的源仓库 URL。
  - **rev**：指定仓库的版本，可以是 Git 标签或提交哈希值。
  - **hooks**：定义在该仓库中要使用的钩子列表。
    - **id**：钩子的唯一标识符。
    - **其他选项**：钩子的具体配置，如 language_version，这取决于具体的钩子。

#### repos配置

在 .pre-commit-config.yaml 配置文件中，repos 配置是用于定义一组你想要使用的预提交钩子的仓库。

##### repo

###### 1、git clone 的存储库url

- **定义**：repo 键用于指定预提交钩子的 Git 仓库的 URL。这个 URL 是 pre-commit 工具在安装钩子时用来 git clone 的地址。
- **功能**：它告诉 pre-commit 从哪里获取钩子的代码。

##### rev

###### 1、git clone要拉取的tag或者revision

## protobuf

Protocol Buffers（Protobuf）是由 Google 开发的一种轻量级、高效的结构化数据序列化工具，广泛用于网络通信和数据存储。

### protobuf IDL接口定义语言

Protobuf 使用一种称为接口定义语言（Interface Definition Language，IDL）的语法来定义消息格式。这种定义语言是声明式的，用于指定要序列化的数据的结构。

#### syntax版本

在 Protobuf 中，syntax 关键字用于指定使用的 Protobuf 语法版本。有两个主要的语法版本：

1. **Proto2**：这是 Protobuf 的早期版本。如果你不显式指定 syntax，则默认情况下使用 Proto2 语法。Proto2 提供了基本的功能，但不支持一些后来的语言特性，如映射（map）类型、字段默认值等。

2. **Proto3**：这是 Protobuf 的最新版本。Proto3 语法简化了一些元素，并引入了一些新特性。它不支持字段的默认值（除了标量数值类型外，默认为零值），也不支持字段的可选性（optional）和必要性（required），所有字段都被认为是可选的。

   ```protobuf
   syntax = "proto3";
   ```

#### message消息类型

message 是一种基本的构造块，用于定义结构化数据的模式。可以将 Protobuf 的 message 理解为一种类似于类（class）或结构（struct）的概念，它用于描述数据的结构，包括它包含的字段、字段类型以及字段的规则（如是否可选、是否重复等）。

```protobuf
message Person {
    string name = 1;
    int32 id = 2;
    string email = 3;
}
```

**字段类型和规则**

- **标准类型**：Protobuf 提供了一系列标准的数据类型，包括各种整数类型、浮点数类型、布尔类型、字符串和字节类型等。
- **枚举（Enum）**：可以定义自己的枚举类型，用于限制字段的可能值。
- **其他 Messages**：可以在一个 message 中使用其他 message 类型作为字段类型，从而创建嵌套的数据结构。
- **重复字段**：如果你想要一个字段包含多个值（类似于数组或列表），你可以使用 repeated 关键字。

#### field字段

每个字段（Field）都具有三个基本组成部分：字段类型、字段名称和字段编号。这些组成部分共同定义了消息中的一个特定数据点。

##### 1、字段类型

字段类型定义了该字段可以包含的数据类型。

- **基本类型**：例如 int32, int64, uint32, uint64, bool, float, double, string, bytes 等。
- **枚举类型（Enum）**：一组预定义的常量。
- **消息类型**：可以是任何定义的 Protobuf 消息类型，允许消息嵌套。

##### 2、字段名称

字段名称是在消息中引用该字段的标识符。字段名称在其所属的消息类型中必须是唯一的。

##### 3、字段编号

字段编号是一个唯一的数字标识符，用于在 Protobuf 的二进制格式中标识字段。这些编号在消息的二进制表示中作为键来使用。字段编号的选择遵循以下规则：

- 必须是一个正整数。
- 从 1 到 15 的编号对编码最为高效，因为它们需要较少的字节来表示。因此，这些编号最好分配给频繁出现的或重要的字段。
- 编号 16 到 2047 也相对高效。
- 避免使用 19000 到 19999 之间的编号，因为这个范围被 Protobuf 的实现保留为特殊用途。

### testify

Testify 是 Go 语言中一个流行的测试框架，它提供了一系列有用的功能来简化测试代码的编写

#### 使用assert断言编写单元测试

断言是单元测试中的一个核心概念，它允许你检查程序在特定条件下的行为是否符合预期。

在测试函数中，你可以使用 assert 包提供的各种函数来断言程序的行为。这些函数通常接受至少两个参数：一个是测试对象（*testing.T），另一个是你要进行断言的条件。以下是一些常见的断言函数：

- **assert.Equal(t, expected, actual)**：检查 actual 是否等于 expected。
- **assert.NotEqual(t, notExpected, actual)**：检查 actual 是否不等于 notExpected。
- **assert.Nil(t, object)**：检查 object 是否为 nil。
- **assert.NotNil(t, object)**：检查 object 是否不为 nil。
- **assert.True(t, condition)**：检查 condition 是否为 true。
- **assert.False(t, condition)**：检查 condition 是否为 false。

```go
func Add(a, b int) int {
    return a + b
}

// TestAdd 测试 Add 函数
func TestAdd(t *testing.T) {
    assert.Equal(t, 4, Add(2, 2))
    assert.NotEqual(t, 5, Add(2, 2))
}
```

### goconvey

GoConvey 是 Go 语言的一个测试框架，它完全兼容标准的 go test 工具，同时提供了一些额外的功能，如基于 web 的用户界面、直观的测试结果展示和代码覆盖率报告。GoConvey 的 web UI 特别适合于展示测试结果和覆盖率，使得跟踪和理解测试结果更加容易。

#### 兼容go test，提供可视化ui和覆盖率

GoConvey 的用法和普通的 Go 测试类似，但它提供了一些额外的断言方法和约定，用于编写更加直观的测试。

1. **编写测试**：你可以使用 GoConvey 提供的 Convey 函数来组织你的测试。每个 Convey 块可以包含一个或多个 So 调用，用于实际的断言。
2. **运行测试**：使用 go test 命令运行你的测试，或者启动 GoConvey 的 web 服务器来实时查看测试结果和覆盖率

```go
func Add(a, b int) int {
    return a + b
}

func TestAdd(t *testing.T) {
    Convey("Given two integers", t, func() {
        a := 2
        b := 3

        Convey("When add the two integers", func() {
            result := Add(a, b)

            Convey("The result should be the sum of the two integers", func() {
                So(result, ShouldEqual, a + b)
            })
        })
    })
}
```

**ShouldEqual**是一个比较器。其他的还有**ShouldNotEqual**、**ShouldBeNil** / **ShouldNotBeNil**、**ShouldBeTrue** / **ShouldBeFalse**、**ShouldBeLessThan** / **ShouldBeGreaterThan**、**ShouldBeLessThanOrEqualTo** / **ShouldBeGreaterThanOrEqualTo**、**ShouldContain** / **ShouldNotContain**（一个集合（如切片、数组、字符串）包含或不包含某个元素）、**ShouldBeEmpty** / **ShouldNotBeEmpty**、**ShouldResemble**（两个复杂的数据结构（如切片、映射、结构体）在结构上相似）、**ShouldPanic** / **ShouldNotPanic**

当使用 GoConvey 进行测试时，它可以自动生成测试覆盖率报告，并在其 Web UI 中可视化地展示这些信息。和其他测试工具一样，高覆盖率并不总能保证代码质量。它更多地是一个指标，帮助你理解哪些代码未被测试。

### gomonkey

用于在测试中进行 mock 和打桩（Stubbing）。它提供了一种便利的方式来覆盖和改变函数、方法和变量的行为。

#### mock打桩工具

- **打桩（Stubbing）**：通常指替换掉函数或对象的某些部分，提供预设的返回值或行为。打桩的关注点在于"替代"。
- **Mocking**：更多地关注于"模拟"一个对象的行为，并检查对该对象的交互是否符合预期。Mock 对象通常用于验证是否进行了特定的调用、调用次数或调用的顺序。

**主要特点**

1. **函数打桩**：gomonkey 允许你修改函数的实现，这在测试函数的不同行为或测试函数的边缘情况时非常有用。
2. **方法打桩**：你可以改变结构体的方法实现，这对于测试依赖于特定方法行为的代码很有帮助。
3. **变量打桩**：gomonkey 可以修改全局变量的值，这在测试需要不同配置或状态的代码时非常方便。

```go
package mypackage

func SomeFunction() int {
    return 10
}

type MyStruct struct {}

func (m *MyStruct) SomeMethod() int {
    return 20
}
```

```go
func TestSomeFunction(t *testing.T) {
    patches := gomonkey.ApplyFunc(mypackage.SomeFunction, func() int {
        return 15
    })
    defer patches.Reset()

    assert.Equal(t, 15, mypackage.SomeFunction())
}

func TestSomeMethod(t *testing.T) {
    myStruct := &mypackage.MyStruct{}
    patches := gomonkey.ApplyMethod(reflect.TypeOf(myStruct), "SomeMethod", func(_ *mypackage.MyStruct) int {
        return 25
    })
    defer patches.Reset()

    assert.Equal(t, 25, myStruct.SomeMethod())
}
```

**注意**

- **测试隔离**：使用 gomonkey 时要确保测试之间相互独立，以避免测试间的相互影响。
- **清理**：在测试结束时，使用 defer patches.Reset() 来清理和恢复原始行为，确保不会影响到其他测试。

   - 在 Pre-request 脚本或 Tests 脚本中，可以使用 pm.environment.get("variableName") 来获取环境变量的值。

- **常用技巧**

1. **避免硬编码**：使用环境变量存储 API 端点、认证令牌和其他可能变化的信息，以减少硬编码和易于维护。
2. **敏感数据安全**：不要在环境中存储敏感信息，如生产数据库的凭证。对于这些信息，可以使用 Postman 的全局变量或集合变量，或者在本地环境中存储。
3. **共享环境**：如果你在团队中使用 Postman，可以共享环境设置，以确保团队成员都在相同的配置下工作。
4. **动态设置变量**：在 Tests 脚本中，可以使用 pm.environment.set("variableName", value) 动态设置环境变量的值，这对于处理 API 响应中返回的数据特别有用。
5. **参数化测试**：使用环境变量进行参数化测试，可以对 API 进行更加灵活和全面的测试。

## 网络抓包

### 学会使用finddler、charles进行http抓包、调试

finddler可以保存会话数据，以便日后分析或与他人共享。Charles 提供了映射本地文件的功能，允许你测试本地变更而无需部署到服务器。

### 学会使用Wireshark、Tcpdump等工具进行网络抓包，进行网络协议分析

使用 Wireshark 的强大过滤功能来缩小分析范围，例如 tcp.port == 80 或 http。可以跟踪特定的 TCP 流来分析特定会话的数据。可以保存捕获的数据包进行后续分析，或者导出特定的数据包或数据流。

打开终端，使用 Tcpdump 命令开始捕获数据包。例如：tcpdump -i eth0 会捕获通过接口 eth0 的所有数据包。可以使用复杂的过滤表达式来捕获特定类型的数据包。例如，tcpdump -i eth0 'port 80' 仅捕获经过端口 80 的数据包。可以将捕获的数据包保存到文件中，例如：tcpdump -i eth0 -w capture_file.pcap。
