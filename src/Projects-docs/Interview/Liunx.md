# 内核基础概念

### 文件系统

#### 树形结构

##### 1、/bin：存放二进制可执行命令目录

/bin 目录包含了许多用户级的基本命令和程序。这些命令和程序对于系统启动和运行是必需的。例如，常见的命令如 ls, cp, mv, cat 等都存放在这个目录下。

##### 2、/lib：存放标准程序设计库目录，又叫动态链接共享库目录

/lib 目录包含了系统运行时所需的基本共享库文件和内核模块。这些库文件被系统上的许多程序共享使用，类似于 Windows 中的 DLL 文件。

##### 3、/etc：存放系统管理和配置文件目录

/etc 目录包含了系统的配置文件。这些文件由系统管理员管理，用于配置系统的各种服务和应用程序。例如，网络配置文件、启动脚本、用户账户信息等。

##### 4、/user：最庞大的目录，存放应用程序和文件目录

/usr 目录包含了用户级的应用程序和文件。它通常包括系统默认的应用程序、库文件、文档等。例如，许多标准的 Linux 发行版将额外的软件和应用程序安装在 /usr/bin、/usr/lib 和 /usr/local 等子目录中。

##### 5、/proc：虚拟目录，是系统内存的映射，可直接访问这个目录来获取系统信息

/proc 是一个特殊的虚拟文件系统，它提供了对内核内部数据结构和运行中的进程信息的访问接口。访问 /proc 目录可以获取系统信息，如 CPU 信息、内存使用情况、正在运行的进程等。它不占用磁盘空间，因为它只是内存中数据的直接映射。

### 内存管理

#### 段页式管理

**基本概念**

- **物理内存和虚拟内存：**

  - 物理内存是计算机的实际内存（RAM）。

  - 虚拟内存是硬盘上的一个区域，操作系统用它来扩展物理内存的容量。

- **分页：**

为了管理虚拟内存，操作系统将内存分成固定大小的块，称为“页面”或“页”。相应地，硬盘上的虚拟内存空间也被分成同样大小的“页框”。

**页面置换的过程**

当程序运行时，它可能需要比物理内存更多的内存空间。操作系统使用页面置换算法来管理内存中哪些页面应该保留，哪些应该被移出到硬盘上：

- **页缺失：**

当一个程序尝试访问的数据不在物理内存中时，就会发生“页缺失”（Page Fault）。这时，操作系统需要从硬盘中的虚拟内存区域加载所需的页面到物理内存中。

- **选择页面换出：**

如果物理内存已满，操作系统必须先从物理内存中移除一个页面，以便为新页面腾出空间。这就是“页面置换”：选择并移除物理内存中的某个页面。

##### 页面置换算法

###### 1、FIFO（先进先出）

FIFO 算法是最简单的页面置换算法。它基于一个简单的原则：最先进入内存的页面将是最先被换出的。FIFO 维护一个队列，以记录页面进入内存的顺序。当需要页面置换时，最先进入内存的页面（队列的头部）被选择并换出。

###### 2、LRU（最近最少使用）

LRU 算法基于这样一个观察：经常被访问的页面很可能在未来也会被访问。因此，这个算法会换出最长时间未被访问的页面。LRU 实现起来比 FIFO 复杂，因为它需要记录每个页面的访问历史。

###### 3、LFU（最不经常使用）

LFU 算法基于一个假设：如果一个页面在过去被访问次数少，那么将来被访问的可能性也低。因此，该算法会选择访问次数最少的页面进行置换。LFU 需要跟踪每个页面的访问频率，这可能会导致算法的开销较大。

###### 4、Clock（时钟算法）

Clock 算法是一种近似 LRU 算法的实现，但开销更小。它维护一个类似时钟的循环链表，每个页面都有一个使用位。当一个页面被访问时，其使用位设置为 1。页面置换时，算法从当前位置开始，顺时针检查每个页面的使用位。如果找到一个使用位为 0 的页面，它就被置换出去。如果使用位为 1，则将其设置为 0，并继续检查下一个页面。这种方式可以近似地找到最少使用的页面，同时避免了频繁的页面访问历史记录。

#### 多级Cache

现代计算机系统通常采用多级缓存（Cache）来提高数据访问速度和整体性能。Cache 是一种快速但容量较小的存储器，用于暂存频繁访问的数据，从而减少对较慢主存（内存）的访问次数。

#### 内存拷贝

内存拷贝是指在计算机系统中将数据从一个内存区域复制到另一个区域的过程。

##### 1、Zero-Copy

Zero-Copy一种减少 CPU 拷贝操作的技术，目的是减少不必要的数据复制，从而提高性能和减少延迟。在传统的数据传输过程中，数据可能需要在用户空间和内核空间之间多次拷贝。Zero-Copy 通过避免这些拷贝操作，直接在内核空间完成数据传输。

##### 2、MMAP

MMAP（内存映射）是一种文件数据映射到进程地址空间的技术。使用 MMAP，文件数据可以直接映射到进程的地址空间，避免了从内核空间到用户空间的拷贝，从而提高了数据处理的效率。

##### 3、DMA

DMA 是一种允许硬件子系统（如磁盘驱动器、图形卡等）直接读写主存储器的技术，无需 CPU 干预。DMA 用于高速数据传输，特别是在大量数据需要在内存和外设之间快速移动时非常有效。通过使用 DMA，CPU 被解放出来处理其他任务，同时数据传输也更高效。

#### 了解常用符号的含义如：&、|、>等

- **&（后台运行）**

 当你在命令的末尾添加 &，它会将该命令放入后台执行。这意味着你不需要等待命令完成就可以继续在同一个 Shell 中执行其他命令。

**常用场景：** 当你需要运行一个耗时较长的进程，而同时又想继续在命令行中执行其他操作时。

- **|（管道）**

管道符号 | 用于将一个命令的输出作为另一个命令的输入。它是连接多个命令的强大工具，使得命令的输出可以直接作为另一个命令的输入。

**常用场景：** 当你需要将一个命令的输出进行进一步处理时。

```bash
cat file.txt | grep 'something'
```

这个命令会先显示 file.txt 的内容，然后 grep 命令会从这些内容中搜索含有 'something' 的行。

- **>（重定向输出）**

 用于将命令的输出重定向到一个文件中，覆盖文件原有的内容。如果指定的文件不存在，Shell 会创建这个文件。

**常用场景：** 当你想将命令的输出保存到文件中时。

```bash
echo "Hello World" > output.txt
```

这个命令会创建（或覆盖）output.txt 文件，并将 "Hello World" 写入该文件。

- **>>（追加重定向）**

**>>** 与 **>** 类似，但它是追加数据到指定文件的末尾，而不是覆盖原有内容。

**常用场景：** 当你想在不删除原有数据的情况下向文件添加内容时。

```bash
echo "Another line" >> output.txt
```

这个命令会在 output.txt 文件的末尾追加文本 "Another line"。

### 网络通信

#### TCP/IP基础

#### 三次握手

##### 1、建立连接过程

- **第一次握手（SYN）**：

  - 客户端发送一个 SYN（同步序列编号）报文到服务器，并指明客户端打算连接的服务器的端口，同时将自己的初始序列号发送给服务器。

  - 客户端此时进入 SYN-SENT 状态。

- **第二次握手（SYN-ACK）**：

  - 服务器接收到客户端的 SYN 报文后，需要确认客户端的 SYN，同时自己也发送一个 SYN 请求。
    - 服务器此时发送一个 SYN-ACK 报文回给客户端。该报文中同时包含服务器的初始序列号。

  - 服务器进入 SYN-RECEIVED 状态。

- **第三次握手（ACK）**：

  - 客户端接收到服务器的 SYN-ACK 报文后，发送一个 ACK 确认报文。

  - 一旦服务器接收到这个 ACK 报文，连接建立成功，服务器进入 ESTABLISHED 状态。

  - 客户端也在发送 ACK 后，进入 ESTABLISHED 状态。

#### 四次挥手

##### 1、断开连接过程

- **第一次挥手（FIN）**：

  - 当数据传输完成后，连接的发起方（假设为客户端）发送一个 FIN 报文，表示已经没有数据要发送了。

  - 客户端此时进入 FIN-WAIT-1 状态。

- **第二次挥手（ACK）**：

  - 服务器接收到这个 FIN 报文后，发送一个 ACK 确认报文，并进入 CLOSE-WAIT 状态。

  - 客户端在接收到 ACK 后，进入 FIN-WAIT-2 状态。

- **第三次挥手（FIN）**：

  - 服务器在发送完所有剩余数据后，发送一个 FIN 报文给客户端，请求关闭连接。

  - 服务器进入 LAST-ACK 状态。

- **第四次挥手（ACK）**：

  - 客户端接收到服务器的 FIN 报文后，发送一个 ACK 确认报文，并进入 TIME-WAIT 状态。

  - 经过一段时间后，客户端关闭连接，进入 CLOSED 状态。

  - 服务器在接收到最后一个 ACK 后，也关闭连接，进入 CLOSED 状态。

#### time_wait状态

##### 1、主动关闭方在收到被动关闭方的FIN包后并返回ACK后，会进入TIME_WAIT状态，等待2MSL（最大报文段生存时间）后关闭

#### close_wait状态

##### 1、表示被动关闭方等待关闭，当收到对方调用close函数发送的FIN报文时，回应对方ACK报文，此时进入CLOSE_WAIT状态

### I/O多路复用

I/O多路复用是一种有效的I/O处理模式，它允许单个进程或线程监视多个文件描述符，等待一个或多个I/O条件成為真，如可读、可写或错误等。主要的I/O多路复用技术包括 select、poll 和 epoll。

#### 阻塞/非阻塞

- **阻塞I/O**

  - **定义**：在阻塞I/O模型中，系统调用（如读取或写入数据）会导致执行它的进程或线程挂起，直到操作完成或发生错误。

  - **行为**：如果数据不可用（如网络数据还未到达），进程会停止执行，直到数据到达并被处理，进程才恢复运行。

- **非阻塞I/O**
  - **定义**：非阻塞I/O允许系统调用在数据不可用时立即返回，而不是等待，即使操作实际上并未完成。
  - **行为**：当数据不可用时，系统调用会返回一个特定的错误码，通知调用者数据尚未准备好。应用程序可以继续执行其他任务或定期检查I/O操作是否可以进行。

- **I/O多路复用与阻塞/非阻塞**

  - **使用非阻塞模式**：I/O多路复用通常与非阻塞I/O一起使用。这意味着即使某个I/O操作不立即完成，应用程序也可以继续执行，例如，监视其他文件描述符。

  - **减少阻塞**：通过监视多个I/O流，I/O多路复用可以在一个流不可用时转向另一个流，从而减少阻塞和空闲时间。

  - **效率提升**：这种方法可以使单个线程或进程高效地管理多个I/O操作，特别适用于需要处理大量并发连接的服务器，如Web服务器或数据库服务器。

#### 同步/异步

- **同步I/O**

  - **定义**：在同步I/O模型中，一个 I/O 操作（如读取或写入）会引起请求它的进程阻塞，直到操作完成。

  - **行为**：应用程序在发起 I/O 请求后，必须等待 I/O 操作完成才能继续执行。这意味着应用程序的后续操作必须等待，直到 I/O 请求得到满足。

  - **例子**：传统的 read() 或 write() 系统调用是同步操作，因为调用它们的进程会一直等待，直到数据被读取或写入。

- **异步I/O**

  - **定义**：在异步I/O模型中，I/O 操作的发起和完成是分离的。应用程序发起一个 I/O 操作后，可以立即继续执行，不必等待 I/O 操作完成。

  - **行为**：应用程序在请求 I/O 操作后继续执行其他任务。当 I/O 操作实际完成时，操作系统会以某种方式（如回调函数、信号或事件）通知应用程序。

  - **例子**：POSIX AIO（异步I/O）是异步操作的一个例子。应用程序可以启动一个读操作，而不用等待它完成就继续执行。

- **同步/异步与阻塞/非阻塞的关系**

  阻塞和非阻塞通常描述的是程序在等待 I/O 完成时的状态，同步和异步则描述的是 I/O 操作本身的完成方式。

#### select/epoll

select 和 epoll 是两种在现代操作系统中常用的 I/O 多路复用技术。

**select**

- **工作原理**：select 函数允许应用程序监视一系列文件描述符，以了解是否有一个或多个文件描述符准备好进行读取、写入或是否有异常。应用程序列出所有感兴趣的文件描述符，然后调用 select，该调用将阻塞，直到这些文件描述符中的一个或多个变为活动状态。
- **限制**：
  - **文件描述符数量限制**：select 通常受限于能够监视的文件描述符的数量（通常是 1024）。
  - **缩放问题**：每次调用 select 时，都需要重复指定整个文件描述符集合，这在处理大量文件描述符时可能导致性能问题。
- **适用场景**：对于文件描述符数量较少的应用，select 是一个简单且有效的选择。

#### epoll

- **工作原理**：epoll 是一种更高效的 I/O 多路复用技术，特别是在处理大量连接时。与 select 不同，epoll 使用一个事件列表，应用程序只需告知 epoll 哪些文件描述符发生了变化。epoll 然后会通知应用程序哪些文件描述符真正准备好进行读取或写入。
- **优势**：
  - **无文件描述符数量限制**：epoll 不受文件描述符数量的限制，它能够处理数千甚至数万个并发连接。
  - **效率更高**：由于 epoll 只关注活动的文件描述符，因此它在处理大量文件描述符时比 select 更有效率。
  - **边缘触发和水平触发**：epoll 支持边缘触发（ET）和水平触发（LT），提供更灵活的事件处理方式。
- **适用场景**：对于需要处理大量并发连接的高性能服务器，如 Web 服务器或数据库服务器，epoll 是一个更好的选择。

### HTTP协议

HTTP（超文本传输协议）是用于从服务器传输超文本到本地浏览器的应用层协议。它基于请求/响应模型。

#### Header和Body的结构

- **HTTP Header**

  HTTP 头部是由关键字/值对构成的，每对之间用冒号 : 分隔。头部用于传递关于 HTTP 请求或响应的元数据。头部信息可以包含以下内容：

  - **请求头/响应头**：包含执行请求或响应所需的信息。例如，User-Agent（请求头，标识发出请求的浏览器类型），Content-Type（实体头，指示资源的 MIME 类型），Accept（请求头，指示客户端能夠处理的内容类型）等。

  - **一般头**：既可以用于请求头也可以用于响应头。例如，Connection（控制是否持久连接）、Date（消息创建日期）等。

  - **实体头**：定义了关于实体主体（如有）的信息，或者无论消息是否包含主体都适用的那些信息。例如，Content-Length（实体主体的大小）、Content-Encoding（实体主体应用的编码类型）等。

- **HTTP Body**

  HTTP 主体则是可选的，用于传输请求或响应的实际数据。它可以包含文本、二进制数据，甚至是文件。主体的具体内容和格式取决于 HTTP 方法（如 GET, POST）和 Content-Type 头部的值。

  - **文本类型数据**：例如，HTML、XML、JSON 等格式的数据。
  - **二进制数据**：如图片、音频、视频文件等。
  - **表单数据**：当使用表单提交数据时（通常是 POST 请求），主体会包含表单输入的内容。

```makefile
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: text/html
Accept-Language: en-US,en;q=0.5
Connection: keep-alive
```

GET /index.html HTTP/1.1 是请求行，接下来的部分是 HTTP 头部，而请求主体在这个例子中是空的，因为 GET 请求通常不包含主体。

#### 状态码含义

HTTP 状态码是由三位数字组成，用于表示 HTTP 请求的响应状态。这些状态码由 IETF 和 W3C 在 RFC 2616 和 RFC 7231 中定义，分为五类。

- **1xx: 信息性状态码（Informational）**

  - **100 Continue**: 请求已被接受，客户端应继续发送请求的其余部分。

  - **101 Switching Protocols**: 请求者已要求服务器切换协议，服务器已确认并准备切换。

- **2xx: 成功状态码（Successful）**

  - **200 OK**: 请求成功。根据不同的请求方法，操作可能会有所不同。

  - **201 Created**: 请求成功并且服务器创建了新的资源。

  - **202 Accepted**: 服务器已接受请求，但尚未处理。

  - **204 No Content**: 服务器成功处理了请求，但没有返回任何内容。

- **3xx: 重定向状态码（Redirection）**

  - **301 Moved Permanently**: 请求的网页已永久移动到新位置。

  - **302 Found**: 服务器目前从不同位置的网页响应请求，但请求者应继续使用原有位置来进行将来的请求。

  - **304 Not Modified**: 自从上次请求后，请求的网页未修改过。

- **4xx: 客户端错误状态码（Client Error）**

  - **400 Bad Request**: 服务器无法理解请求的格式，客户端不应该尝试再次使用相同的内容进行请求。

  - **401 Unauthorized**: 请求未授权。

  - **403 Forbidden**: 禁止访问。

  - **404 Not Found**: 服务器找不到请求的网页。

  - **408 Request Timeout**: 服务器等候请求时发生超时。

- **5xx: 服务器错误状态码（Server Error）**

  - **500 Internal Server Error**: 服务器遇到错误，无法完成请求。

  - **501 Not Implemented**: 服务器不支持请求的功能，无法完成请求。

  - **503 Service Unavailable**: 服务器目前无法使用（由于超载或停机维护）。

#### HTTPS原理

##### 1、对称/非对称加密

HTTPS（超文本传输安全协议）是 HTTP 的安全版本，它在 HTTP 的基础上通过加密和安全认证提供了数据传输的安全性。HTTPS 的安全性主要依赖于对称加密和非对称加密的结合使用。

- **非对称加密**：
  - **原理**：使用一对密钥，一个公钥（public key）和一个私钥（private key）。公钥用于加密数据，私钥用于解密数据。公钥是公开的，而私钥是保密的。
  - **用途**：在 HTTPS 握手过程中，非对称加密用于安全地交换对称加密的密钥。
  - **优点**：安全性高，因为即使公钥被公开，没有私钥也无法解密信息。
  - **缺点**：相对于对称加密，处理速度慢。
- **对称加密**：
  - **原理**：使用同一个密钥来加密和解密数据。
  - **用途**：一旦在 HTTPS 握手过程中安全地交换了对称密钥，所有后续的数据传输都使用这个对称密钥进行加密和解密。
  - **优点**：处理速度快，适合加密大量数据。
  - **缺点**：密钥的安全传输是一个挑战，因为发送方和接收方都需要知道这个密钥。

**HTTPS工作原理**

a.**客户端发起请求**：浏览器向服务器发送一个 HTTPS 请求。

b.**服务器响应**：服务器返回一个包含其公钥的数字证书。

c.**密钥交换**：

- 客户端验证服务器证书的合法性（通常是通过预安装的根证书）。
- 客户端生成一个随机的对称密钥，然后使用服务器的公钥对这个密钥进行加密，并发送给服务器。
- 服务器使用自己的私钥解密这个消息，获取对称密钥。

d.**安全通信**：双方使用这个对称密钥进行加密通信。
